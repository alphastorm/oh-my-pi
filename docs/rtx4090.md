## Current K3/K5 status

K3 stopped at the first real restart red after one passing MTP0 Golden run. The rehash root cause is fixed and a remediated package candidate passes local/no-service package and lifecycle verification, but it has not run fresh live K3; MTP3/K5 did not run. The public release artifact and green Workstream K qualification receipt are not published, so `availability.installable` remains `false`.

MTP0 is the incumbent and remains the registry truth until the full observed gate passes. Do not describe an MTP3 binary as qualified, promoted, or active merely because it builds or serves requests.

A prior deterministic long-session persistence run is useful baseline evidence. It does not, by itself, bind the current K3/K5 source, package, config, or speculation mode and is not the current release receipt.

## Bounded MTP3 gate

After protocol parity, run one bounded MTP3 requalification:

1. Fixture P protocol/tool correctness;
2. Fixture L 80–120K continuation, cache, and restart;
3. Fixture G once on the real Golden implementation task.

Promote MTP3 only if the exact candidate has:

- no malformed protocol, tool, or response behavior;
- at least 10% improvement in complete Golden wall time;
- exact persistence and continuation behavior.

Otherwise keep MTP0, record the result, and close the experiment. Do not broaden into MTP5 or a model/kernel tournament.

## Fleet placement

For a validated fleet, fresh background work prefers this profile. With `appliance.foregroundReservation=true`, the RTX 5090 remains available for new foreground or vision work when this profile is healthy and compatible.

Placement never overrides capability, context, authenticated status, warm affinity, or saturation checks. The explicit alias `qwen38-4090` constrains the request to this profile. A failure does not fall through to cloud; optional cold-local fallback can choose only another compatible authenticated local appliance and forces full replay.

## Durable checkpoint status

The profile declares `durable-checkpoint`, OMP implements the exact save/status/delete client, and the matching NInfer source/host contracts pass. The canonical `sm_120a` binary and live process-restart proof remain blocked on the held RTX 5090 lane. Capability declaration is not durability evidence.

Before release, D6 must prove on the exact candidate:

- save after a complete response;
- authenticated checkpoint status;
- actual NInfer process restart;
- restoration and exact long-session continuation;
- deterministic full replay for missing, corrupt, incompatible, disabled, or deleted state;
- delete behavior and content-safe receipts.

Until then, claim only OMP restart continuity that was actually observed; do not claim NInfer restart continuity. See [Session continuation](./session-continuation.md).
