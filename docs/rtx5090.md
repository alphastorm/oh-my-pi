# RTX 5090 Linux appliance

`rtx5090-linux` is the foreground and vision target for the Qwen3.8 local appliance. The registry describes the intended release identity; it does not make an unpublished image installable.

The profile requires Linux, an RTX 5090 with at least 32 GiB VRAM, Docker, NVIDIA Container Toolkit, and secure appliance secret storage.

## Current release status

The source-provenance problem has been remediated. The clean NInfer release source is at `ae044b45259e46ca652e64e6b9f9672121ef4518`, and the packaging handoff is defined.

The release is still held:

- the isolated RTX 5090 image build has not run;
- no candidate binary/image and runtime receipts bind to that source head;
- the runtime asset location and checksum are not published;
- the public qualification receipt is not published;
- the model artifact URL is not published;
- no fresh-install or rollback proof exists for this candidate.

Accordingly, `availability.installable` remains `false`. `omp appliance doctor` and `plan` report the blockers; `install` must refuse the profile.

Previous RTX 5090 performance or quality measurements are not automatically evidence for this remediated head. Do not quote them as candidate results unless a new receipt binds the exact source, image, model, config, deployment profile, and observed run.

## Placement contract

For a validated fleet, fresh foreground work prefers this profile after compatibility and saturation checks. Vision requests require this profile because the RTX 4090 profile does not declare vision. Background work avoids the RTX 5090 when a compatible RTX 4090 is available and `appliance.foregroundReservation` retains its default `true` value.

Warm-owner affinity still takes priority. A session already bound to another healthy endpoint is not moved merely because the RTX 5090 is preferred for new foreground work. If its warm owner disappears, OMP fails unless explicit cold-local fallback is enabled; even then, recovery is full replay on another local endpoint, never cloud fallback.

## Qualification required before install

The exact candidate must pass:

1. a clean `sm_120a` image build with immutable image and binary digests;
2. authenticated status identity matching source, patch stack, binary, artifact, config, profile, and served model;
3. Fixture P protocol/tool correctness;
4. Fixture L 80–120K continuation, cache, and restart behavior;
5. Fixture G once for the release candidate;
6. fresh isolated install, routed proof, and rollback proof;
7. a content-safe public qualification receipt and published asset checksums.

The registry's MTP3 and BF16 declarations are release targets, not substitutes for those observations. A clean build alone does not satisfy the gate.

## Read-only inspection

```sh
omp appliance doctor --json
omp appliance plan qwen3.8 --gpu rtx5090 --json
omp appliance status --json
```

These commands do not build an image, start a service, alter a route, or authorize release. The expected current plan is blocked.
